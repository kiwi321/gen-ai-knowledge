I · 空间生成

GPT-6 Astra 这一周刷屏的真正对象，不是「更漂亮的 3D 图」，是把一句描述变成还能继续工作的空间。

核心命题

空间生成的验收标准是可编辑性：网格、材质、关卡逻辑、浏览器工程，而不是最终那一帧。视频模型可以伪造一次浏览，给不了第二次修改。

原理

四条机制，够推出这一周几乎所有 3D demo

1. 交付物分层

从易到难：单张概念图 → 可渲染网格 → 可交互场景 → 可过夜生长的世界。每一层多一个约束：拓扑、碰撞、时间。帖子里「重建艺术宫」「蒸汽火车 3295 个对象」「浏览器卡丁车」「一周曼哈顿」看起来五花八门，其实只是停在这一条链的不同位置。

2. 没有风格靶，模型会在「还行」处停住

纯文本描述对美术方向是欠定的。要画质，先用图像生成做出目标截图，再让模型用视觉对比游戏内画面去逼近。这不是提示词写得更长，是给优化过程一个可比较的损失。Anshu 说的 “the trick is image gen”，是这条机制的一种实现，不是魔法。

3. 屏幕是未做 API 的软件的接口

Blender、Unreal、KiCad、Canva 学习成本高、功能完整、AI 接口落后。Agent 不必等官方插件：把 GUI 当工具面，computer use 就能进这些软件。以前的路线是先包 MCP / API 再教模型用；现在多了一条「先会用软件，再谈封装」。

4. 世界尺度是长程问题

一条 prompt 能做的是局部场景。街道级、城市级、多 agent 共生，需要 Manager Loop / /goal 这种按天计的循环：巡检、修补、再巡检。5 天还没做完的 SimCity clone，说明的是任务形态变了，不是「一句话出 3A」。

可由 @willlhhh 的判断、 @anshuc 的画质闭环、以及 Unreal / Blender 过夜 demo 反推。

选型

先选载体，再谈模型

你要的东西载体为什么不要指望
能转发的可玩小东西 浏览器 + three.js / WebGL 零安装、好传播、和 Codex/Sites 同一运行时 写实、复杂物理、大型世界。风格应主动走动森 / 塞尔达 / voxel，避开 three.js 的写实短板。
还能改的资产 Blender（MCP 或 computer use） 对象是 mesh、材质、相机，后续可进任何管线 一次出片就结束。价值在工程文件还在。
开世界 / 引擎级 Unreal + 长程循环 按街道、按关卡迭代，适合过夜 当天交稿。病毒视频里的「一周」是真实量级。
只看一次的浏览感 视频模型（体系 II） 像素成本低 改一扇门、换一条路线。没有场景图。

模型对照只在同一载体上有意义。Astra 在 Blender 场景上相对 Sol 是明显一跳，Kimi K3 用更低成本贴近；Fable 5.1 在单次 3D 对打里被说成肉眼落后——但那是同一天、同一提示、同一次运行，只能当弱证据。

方案

四种社区已跑通的做法

方案 A · 画质优先

图像生成当损失，Blender 当优化器

Codex 接 Blender MCP → 用 image gen 出目标画风概念图 → 迭代直到游戏内截图接近概念图，并钉死 60fps → 推理 High。贴图也由 image gen 喂给 mesh，不引入外部资产。适合「看起来要像作品」的小场景。45 分钟那次是画面 demo，不是完整玩法。

方案 B · 传播优先

一句话网页 3D，风格服从框架

明确：网页、three.js、Vite、可旋转缩放、角色与道具要可扩展。主动指定圆角 / 像素 / 二次元，把引擎短板写成风格。适合玩具、展示、验证空间想法。nocoo 的儿童空间是这个模板。

方案 C · 有参考物

照片、扫描、图纸 → 可编辑几何

输入可以是建筑照片、房产图、老图纸、室内扫描。约束写成：不下载现成资产、材质从参考里长出来、对象可拆可改。适合重建、展示、地产、档案。Zillow / Apple Park / 蒸汽火车 / 客厅扫描都是同一方法的输入替换。

方案 D · 世界尺度

长程循环，按区块验收

把世界切成可检查的单位（一条街、一个房间、一个系统），让 Agent 过夜巡检。验收不是「看起来酷」，是下一块还能接上。适合开世界和多 agent 场景；工期按天，不是按分钟。

方案 A 的操作说明（社区方案）
Connect Codex to Blender MCP.
1) Generate concept images of the target art style with image gen.
2) Model every asset in Blender. Use image gen for mesh textures. No external assets.
3) Iterate until in-game screenshots match the concept images as closely as possible, running at 60fps.
4) High reasoning.
Art direction example: sad but beautiful dystopian theme, voxel-ish, lighting that feels real and physical.
方案 B 的结构模板（社区方案）
新项目，网页3D，threejs。
角色：____（身份、年龄、外观，动作要可区分）。
空间：____（面积、焦点、分区；哪些可扩展成独立模型）。
风格：主动规避 three.js 写实短板，采用圆角 / 像素化 / 二次元（或动森、塞尔达）。
相机：支持缩放旋转。构建：Vite，本地可跑、可热刷新。
验收：不是一张图，是可继续加道具和动作的工程。
纠错

不要从这一周的帖子推出这些

「Astra 是世界级 Blender 选手」 → 更准确：它的优势是三维推理 + 会用软件。网格质量和资深 TD 比，demo 选择偏差极大；有人直接指出那不是 world-class Blender。

「45 分钟做出 3D 游戏」 → 作者后来澄清：要的是画面 demo，玩法还在跑；three.js、无外部依赖。完整游戏仍是长程任务。

「前端 / 游戏行业要完了」 → computer use 降低的是从零到可玩原型的门槛。物理、网络同步、工具链、性能、内容管线没有消失。KiCad 排 PCB、Canva 画像，证明的是「能进专业 GUI」，不是「能替代专业流程」。

「Fable 已经不能看 / Astra 全面碾压」 → 单次对打，且有人报告 Fable 当天懒、重试仍怪。Kimi K3 在成本和速度上是真实竞争者。把病毒视频当排行榜会错。

配额「几乎没掉」 → 绑定 20x Pro、只跑了画面 demo、作者自己也怀疑是不是碰上重置。不能当成本模型用。

II · 视频生成

视频模型擅长补一段连续像素，不持有可查询的空间。所以「一镜穿过七个房间」和「海边随手拍」是两类问题。

核心命题

要空间连续，先建几何再渲染像素；要日常真实感，先锁摄影机缺陷和身份，而不是上更贵的模型。路径选错，提示词再长也补不回场景图。

原理

两条路径，不要共用工作流

路径 α · 空间连续路径 β · 日常手持
要骗过的是 房间关系、相机是否穿模、物体是否还在 这是不是朋友随手拍的：对焦、抖动、曝光、无配乐
真正的约束 先有统一三维空间和同一套视角 身份锁死 + 摄影机语言 + 按秒的事件表
模型角色 视频模型只负责填像素，不负责发明建筑 便宜的视频模型通常够用；贵模型买的是纹理不是「更像监控」
改一处的代价 改场景图，再导出，再生成 —— 这就是 Blender 路线的意义 改提示词里的某一秒，整段重抽

歸藏拿 GPT-6 驱 Blender 的甜甜圈动画去对 Seedance 2.5：可以比观感，但更该比的是下一次修改谁便宜。即梦一条大约 ¥35（384 积分），Codex 套餐口径估 Astra 大约 ¥8——这是个人账单观察，用来建立数量级，不是报价单。H3 有渠道在推约 0.1 元/秒，评论里也有「比 SD 仍差一截」；它适合路径 β，不自动胜任路径 α。

方案

三种做法，对应三种成品

方案 α · 一镜多空间

几何先行，视频后填

故事 → 只定动作 / 区域 / 行进 → 搭本集统一三维空间 → 摆人、道具、相机，走完整条路线 → 关键位置导出同一视角体系的截图 → 故事板 → Seedance（或同类）。可抄的一句：先锁定空间路径，模型只填画面细节。

方案 β · 日常感短片

把「不像广告」写成约束

不必上最贵视频模型。提示词按五锁来写：身份、场景（无品牌无地标）、摄影机缺陷、按秒事件、环境声。禁止云台、无人机、慢动作、配乐、字幕。H3 + 长提示词是这一方案的一种实现。

方案 γ · 已有素材

Agent 剪时间线，不替你拍

素材齐了再用 Codex + ChatCut 这类组合口喷剪。它替代的是剪映操作，不是摄影。Grok bot 则是另一条「图或一句话 → 情绪短片」的入口，适合没有成片管线时的试水。

接到短剧时

分镜层才准碰视频模型

大纲、人设、美术、剧本先收敛（体系 III）。分镜按 2–5 秒切，提示词跟选定的视频模型对账。提前让视频模型「自己想剧」，人物和房间会每张都不一样。

方案 β 的提示词骨架（社区方案，可替换人物与事件）
Create a 30-second, 1080p ultra-realistic home video of the same person doing one unplanned ordinary activity.

LOCK identity: face, hair, outfit, bag, accessories — unchanged throughout.
LOCK setting: real residential streets, no brands, landmarks, ads, or staged crowds.
LOCK camera: older handheld consumer camera. Imperfect framing, shake, autofocus hunting, exposure shifts, motion blur, digital noise, compression. No gimbal, drone, slow motion, commercial polish.
LOCK time: write the 30 seconds in 5-second beats, one concrete action each.
LOCK audio: wind, footsteps, ambience, genuine laughter. No music, narration, subtitles, logos, watermarks.

Realism: physics, hair, fabric, hands, faces. No distortions, duplicated objects, disappearing props, wardrobe changes, anatomy errors.
Final feel: accidentally captured by a friend — intimate, imperfect, spontaneous.
纠错

价格和「谁更强」都容易读错

「H3 全面拥抱，不输 SD」 → 观感接近的是路径 β 的日常片。路径 α 的空间一致性、以及部分人评的「仍差约 20%」，说明 H3 是成本方案，不是上限方案。0.1 元/秒是具体渠道价，换平台会变。

「Blender 动画 vs Seedance 没有可比性」 → 比最终 6 秒片子，确实类别不同。比「改第 3 秒的相机」就完全可比：一边改工程再渲染，一边整段重抽。歸藏后来说这代表一种新可能，这个读法是对的。

视频模型不会「变成游戏引擎」 → 游戏行业被短视频化，说的是内容分发；生产侧只要还要改关卡，就仍要场景图（回到体系 I）。

III · Agent 生产

模型越贵，越不该去读一千个文件。短剧 skill、Fable 进度条、过夜建城，用的是同一套生产约束。

核心命题

智力花在澄清、拆解、验收；执行、检索、改文件、出图交给更便宜的工人。清单如果只写给模型看，等于没有清单——质量门必须是脚本。

原理

把「模型」拆成两个角色

在有分级额度的编码 Agent 里（这一周是 Fable 大约占周额度一半、更贵也更聪明），失败模式只有两种：

  • 智力见底：指挥模型烧得太快，后半周只能降智。
  • 窗口浪费：便宜模型把总进度条先打满，最强模型反而没用完。

所以不是「永远用最强」，是让两条消耗大致同比例下降。做法是角色分离：

  • 指挥：需求澄清、方案、任务分发、抽查结果。强度 High 或 Medium，默认不上 Max——Max 买的是更长的死磕，不是更正确的架构判断，却按最高倍率烧指挥额度。
  • 工人：读大量代码、写、测、批量改。Opus / Sonnet 或同等执行模型。
  • 卫生：换任务 /clear；长任务中途 /compact；每天看两次进度条，哪条超前就反向调。

过夜 Manager Loop、五天 /goal，是同一原则在空间生成上的加长版：指挥者不进引擎抠面，只规定区块和验收。

指挥角色的固定附言（社区方案）
注意你的主要任务是分析、编排和验证，具体任务尽可能交给 subagent 去执行。自己只做需求澄清、方案拆解、任务分发和结果验收。实现类工作（读大量代码、写代码、跑测试、批量修改）一律派给 subagent。不要选 Max 及以上。
实例

收敛式管线：短剧只是写得最清楚的一个例子

任何多步骤生成（短剧、系列视频、大场景）都有同一个结构问题：后面的步骤爱做新决定，于是人物、房间、剧情每张都不一样。收敛规则是：

  1. 先锁结构，再锁人与世界，最后才输出。大纲可以否定后面的一切；分镜不许回头改剧情。
  2. 中间层可来回迭代：人设、美术、剧本互相校对，但不推翻集数与爽点骨架。
  3. 质量门是代码。「主角不要太多」写成 1–5 的校验；「钩子在前 3 拍」写成断言。模型自觉的 checklist 等于没有。
  4. 资产预填，禁止手抄。人物表从大纲长出来，美术吃同一份 JSON，避免第二份真相。

shuohao-skills 把这五步落成可跑的 skill（Claude Code / Codex 都能跑，零 npm 依赖）：

层负责什么门允许的决定
outline改编说明、人物分档、爽点、分集、资产清单14结构。可体检已有大纲。
characters画像、形象 / 音色提示词、设定图—人怎么被看见、被听见
art场景 + 叙事道具、一致性锚点、状态变体11世界长什么样。这步不扎实，后面每张都像不同的剧
script场次 + 节拍；时长按语速算；台词对接 TTS10戏。不管镜头
storyboard2–5 秒分镜 + 图 + 视频模型提示词17只输出，不做新剧情决定

仓库：eternityspring/shuohao-skills。这是短剧领域把原则实现得很彻底的一种方案；换游戏关卡、系列广告，骨架可以原样搬：结构 → 角色/世界 → 剧本 → 镜头。

产品

能秀的能力和每天需要的能力不是同一张清单

收藏里最不像 demo 的一句：智能体眼下最核心的需求可能是总结微信群。接口不开、合规打压、有人做了也不敢开源。它提醒的是体系 III 的验收：生产系统要先问「有没有每日真实输入」，再问「能不能过夜建曼哈顿」。

纠错

额度技巧不是玄学

「两条进度条对齐就赢了」 → 对齐是资源卫生，不提高智力。指挥模型选错任务，对齐也只是整齐地做错。

「Max 一定更强，生产必须开」 → 在这套额度结构里，Max 优先消耗的是稀缺的指挥窗口。大多数拆任务用 High/Medium 更合理。有人第一次就把 5 小时窗口打爆，是用法问题不是模型问题。

「把 checklist 贴进提示词就算质量门」 → 短剧 skill 的主张相反：门必须能 validate 失败。不能失败的门，只是文案。

IV · 界面生成与接入

同一套权重，对话网页、Studio、编码 Agent、礼品卡钱包，接到的根本不是同一层能力。

核心命题

界面生成停在可运行原型；再往前是工程。用模型之前，先问你进的是哪一个入口——入口决定上下文、工具、配额和能不能 computer use。

原理

先理解产品，再出页；页不是系统

设计向插件（Codex 上的 Product Design 是一种）正确的顺序是：定位、用户、场景 → 视觉方向、信息架构、交互 → 可运行页面。它解决的是「从需求到第一版界面」的欠定问题，和空间生成里「先有风格靶」是同一类：先给方向，再填像素。

适用：个人站、Landing、说明页、后台壳、MVP 演示。不适用：权限、数据一致性、设计系统演进、性能、多人协作。评论里「前端要失业」是把原型层当成了工程层；反过来，「工程师用了只是如虎添翼」才是这一层的正确推论。

Gemini 同理：消费级对话网页是产品，Google AI Studio 才是完整的模型选择、参数和构建界面。要「指哪打哪」做前端原型，应走 Studio；当时 3.8 Flash 也是在 Studio 里先测。社区说的「满血」应读成「没被对话产品裁过的那一层」，不是神秘开关。

方案

三种入口，解决三种「用不了」

付账

官方礼品卡进钱包

OpenAI 礼品卡：美国购买和兑换，美元，$15–$250，无有效期。chatgpt.com/redeem 充进 Wallet，可付 Go / Plus / Pro / Business 和部分 credits。它解决支付通道，不解决风控——封号后比苹果 / 谷歌订阅更难退。

机器

Grok Bot 那台电脑就是节点

Bot 自带约 8 核 / 16G / 128G 的 Debian，默认只能聊天代劳。Tailscale SSH 把它拉进你的 tailnet：ssh box@cursor-box.<尾网>.ts.net。PID 1 不是 systemd，开机钩子要单独挂。不要点 Update Grok Bot's Computer 换镜像，会清掉 Tailscale 和登录态。

云

一人公司的基础设施额度

Cloudflare for Startups 的自筹档（公司 <10 年、融资 <$1M、域名邮箱、能看懂的官网、一个公开账号）对应约 $10k / 年。申请本身不收费，但账户要绑付款方式。注意子限额：该档 Workers AI 大约只能抵 $2,500；域名、AI Gateway、China Network 往往不在额度里。以官网当时条款为准。

纠错

入口上的常见读错

「网页版 Gemini 故意残血」 → 更稳的表述：那是对话产品，路由、工具、限流和 Studio 不同。要完整控件就去 Studio，不必阴谋论。

「礼品卡是最安全的订阅方式」 → 对支付摩擦是。对账号安全不是。封号原因更多是环境 / 接口滥用，和是不是礼品卡关系不大，且更难找发卡渠道退款。

「有了 Grok Bot 等于有一台永远的美国 VPS」 → 换镜像即重置。当开发机可以，当不可丢失的服务器不行。
